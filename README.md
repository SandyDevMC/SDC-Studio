# SDC-Studio

Редактор паков одежды для мода **Sandy's Dynamic Clothing**. Позволяет
создавать новые `.cloth`-паки и редактировать готовые без ручной правки
JSON и без ручной сборки архива.

## Запуск

### Windows — обычный `.exe`

Для запуска без консоли используйте готовый `dist\SDC-Studio.exe`.
Если EXE ещё не собран, запустите `build_exe.bat` — скрипт установит PyInstaller
и соберёт оконную версию в `dist\SDC-Studio.exe`.

### Через Python

Нужен Python 3.10+ со стандартным tkinter.

```
python SDC-Studio.py
```

Команда `pip install -r requirements.txt` включает нативный drag-and-drop архива на стартовом экране (`tkinterdnd2`). Без него приложение остаётся рабочим, но файл нужно выбирать вручную.

## Как этим пользоваться

1. При запуске - выбор «Создать новый пак» / «Загрузить готовый», либо
   просто перетащите `.cloth`/`.zip` архив на окно.
2. В паке сверху находятся действия сохранения и настройки, а ниже — список
   предметов. Папка внутри архива показывается отдельной колонкой.
3. Мастер создания предмета идёт по шагам: имя папки → id/имя/описание →
   слот и тип (skin/cape) → броня → слой наложения (layer) или ручной
   priority → текстура → иконка. На текстуре сразу проверяется нужный
   размер (64×64 для skin, 64×32 для cape) - без Pillow, встроенной
   проверкой PNG.
4. После создания/сохранения предмета студия сама спрашивает, добавить ли
   локализацию (переводы `name`/`description` под разными `lang`-кодами,
   например `ru_ru`, `en_us`).
5. «Настройки пака» на экране списка - это `manifest.json` (версия
   формата пака, опционально).
6. «Сохранить» / «Сохранить как…» пишет архив в `.cloth` (это обычный ZIP
   под другим расширением — так же, как его читает мод).

Двойной клик по предмету в списке - редактирование. Если при
редактировании не выбирать новый файл текстуры/иконки - остаются старые
(это явно написано под полем).

## Архитектура: как добавить новый тип файла (для аддонов)

Мастер (`wizard.py`) ничего не знает о `item.json` или `manifest.json`
напрямую - он просто проходит список шагов с полями любого зарегистрированного
`schema.FileSchema` и возвращает словарь введённых значений. Сегодня в
`sdc_studio/schema.py` зарегистрировано два файла:

```python
register_schema("item.json", build_item_schema)
register_schema("manifest.json", build_manifest_schema)
```

Если у аддона (или у новой версии мода) появится свой файл настроек -
описывается точно так же:

```python
def build_my_addon_schema(context: dict) -> FileSchema:
    return FileSchema(
        key="my_addon.json",
        title="Настройки аддона X",
        steps=[
            StepSpec(title="Шаг 1", fields=[
                FieldSpec(key="enabled", label="Включить аддон", kind="bool", default=True),
                FieldSpec(key="threshold", label="Порог", kind="int", default=10),
            ]),
        ],
    )

register_schema("my_addon.json", build_my_addon_schema)
```

Ни `wizard.py`, ни экраны в `ui_*.py` при этом трогать не нужно - им всё
равно, какая именно схема на входе. Доступные виды полей (`FieldSpec.kind`):
`text`, `multiline`, `int`, `float`, `choice`, `choice_editable`, `file_png`,
`bool`. У поля можно задать `validate` (проверка значения, в том числе с
оглядкой на уже введённые в мастере значения) и `visible_if` (скрыть поле,
если оно не имеет смысла при текущих ответах - как `layer`/`priority`,
скрытые для `type: cape`).

## Структура проекта

```
SDC-Studio.py             - точка входа
build_exe.bat              - сборка Windows EXE без консоли
SDC-Studio.spec            - конфигурация PyInstaller
sdc_studio/
  constants.py              - слоты, слои, типы и коды локалей
  png_utils.py              - проверка PNG и чтение размеров без Pillow
  models.py                 - Pack/PackItem, чтение и запись .cloth/.zip
  schema.py                 - декларативные схемы item.json/manifest.json
                             + реестр для новых типов файлов
  wizard.py                 - универсальный пошаговый мастер
  localization.py           - диалог переводов
  ui_welcome.py             - стартовый экран
  ui_items.py               - экран списка предметов пака
  theme.py                  - светлая/тёмная тема и общие стили
  settings.py               - сохранение пользовательских настроек
  app.py                    - сборка окна и обработчики
.github/workflows/
  build-windows.yml         - автоматическая сборка EXE на GitHub
```

## Известные ограничения по формату

Студия читает и пишет самый распространённый вариант раскладки пака -
«одна папка = один `item.json`» (так устроены все примеры в самом моде:
`sandys_classics_pack`, `sandys_frak`, `sandys_trousers`). Редкий вариант,
когда один `item.json` содержит JSON-массив сразу из нескольких предметов,
при загрузке не роняет студию, но такая папка помечается предупреждением и
пропускается - её придётся пересобрать вручную в обычном виде. Всё, что
сама студия записывает, всегда в «простом» формате и гарантированно
читается загрузчиком мода без предупреждений.


## Тёмная тема

Тема переключается кнопкой в правом верхнем углу окна. Выбор темы сохраняется между запусками.

## Сборка Windows EXE

`build_exe.bat` собирает `dist\SDC-Studio.exe` через PyInstaller с `console=False`, поэтому запуск происходит как обычного оконного приложения без консольного окна. В репозитории также есть GitHub Actions workflow `.github/workflows/build-windows.yml`, который может собрать EXE на Windows и прикрепить его к релизу по тегу `v*`.
